# ملاعبي — تطبيق اللاعب PWA (نسخة موسعة v2)

## الشاشات المتضمنة في الإصدار الثاني
- شاشة البداية والتعريف بالتطبيق.
- تسجيل الدخول برقم الهاتف وشاشة OTP (وضع معاينة).
- الرئيسية، البحث والتصفية، تفاصيل الملعب.
- اختيار التاريخ والوقت، مراجعة تفاصيل الحجز، الدفع عند الملعب.
- تأكيد الطلب ورمز QR توضيحي، قائمة الحجوزات وتفاصيل الحجز.
- تقييم الملعب، المحفظة، الملف الشخصي والإعدادات.

## ما تم تنفيذه
- واجهة عربية RTL متجاوبة ومهيأة للهاتف.
- خط Thmanyah Sans المضمّن محلياً بأوزان 300/400/500/700/900.
- صفحات الرئيسية، البحث والتصفية، تفاصيل الملعب، اختيار التاريخ والوقت، مراجعة الحجز، حجوزاتي، الحساب.
- مفضلة محلية، وحفظ حجوزات المعاينة في LocalStorage.
- ملف PWA وService Worker للتثبيت والتخزين المؤقت لملفات الواجهة.
- طبقة API أولية تتبع مسارات OpenAPI المتفق عليها.

## التشغيل المحلي
يتطلب متصفحاً حديثاً. شغّل خادماً ثابتاً من مجلد المشروع:

```bash
python -m http.server 4173
```

ثم افتح `http://localhost:4173`.

## وضع المعاينة
`config.js` مضبوط افتراضياً على `DEMO_MODE: true`. رمز OTP التجريبي هو `1234`. الحجوزات المحفوظة محلية فقط، ولا ترسل إلى خادم ولا تحجز وقتاً حقيقياً.

## ربط API الفعلي
1. انشر API وفق OpenAPI v1 واستبدل `API_BASE_URL` في `config.js` بعنوان API الحقيقي.
2. فعّل تسجيل الدخول عبر `/auth/otp/request` و`/auth/otp/verify` مع إدارة آمنة لرموز الوصول والتحديث.
3. اربط استكشاف المنشآت بـ `GET /venues`، وتفاصيل المنشأة والملاعب، والتوفر بـ `GET /fields/{fieldId}/availability`.
4. يجب أن يرسل إنشاء الحجز `Idempotency-Key` إلى `POST /bookings` وأن يطابق جسم الطلب مخطط OpenAPI حرفياً.
5. لا تفعّل العربون الإلكتروني قبل اعتماد مزود دفع صالح للتشغيل في اليمن.
6. لا تعرض نجاح الحجز إلا بعد استجابة الخادم؛ منع التعارض والتداخل يتم في قاعدة البيانات/الخادم وليس في المتصفح.

## ما لم يكتمل بعد
- لا يوجد Backend أو قاعدة بيانات أو OTP حقيقي في هذه الحزمة.
- بيانات الملاعب والصور والأسعار بيانات عرض تجريبية وليست منشآت أو أسعاراً مؤكدة.
- لم يتم توصيل بوابة دفع، الإشعارات، الخرائط، المراجعات أو QR حقيقي.
- يلزم إكمال اختبار PWA على أجهزة Android/iOS، واختبارات الوصول والأمان، واختبارات عقد API قبل الإنتاج.

## مراجع المشروع المرفقة
- `docs/openapi-v1.yaml`: عقد API المعتمد كخط أساس للتكامل.
- `docs/database-schema-v2-draft.sql`: مسودة مخطط قاعدة البيانات التفصيلي.
- `docs/operational-decisions-schema-patch.sql`: تعديلات القرارات التشغيلية.

هذه الملفات مراجع تصميمية؛ لا تشغّل SQL مباشرة في بيئة الإنتاج قبل مراجعة migrations والقيود واختبارات التزامن.
